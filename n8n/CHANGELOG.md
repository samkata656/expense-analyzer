# n8n change log

Every change to a workflow or prompt gets an entry here. Workflows live in [`workflows/`](workflows/) and are generated by [`generator/build.mjs`](generator/build.mjs); prompts are documented in [PROMPTS.md](PROMPTS.md).

Format: `## [workflow version] - date`, then one line per workflow touched, with the prompt version when a prompt changed.

## [1.4.0] - 2026-11-27
Security audit (/cso) follow-up. Employee codes work as the login secret, so the CFO agent must never see them.
- **Expense Intake**: *Embedding text* and the vector metadata no longer contain `employee_code` (only name and `user_id`).
- **CFO Assistant**: prompt `cfo-v1.1`. The schema hides `employee_code`, `SELECT *` on users is forbidden, and the agent refuses to reveal employee codes.
- **DB** (migration `003_harden_cfo_access.sql`): `cfo_readonly` gets a column-level grant on `users` without `employee_code`, and existing embeddings are scrubbed.

## [1.3.0] - 2026-11-27
- **CFO Assistant**: AI Agent node upgraded 2.2 → 3.1. v2.2 rejects models that run on the Responses API ("This model is not supported in 2.2 version").
- **CFO Assistant**: new *Has reply?* If node. An empty agent answer is logged to `error_logs` and returned as `AI_ERROR` instead of an empty 200.
- **CFO Assistant**: *Luna (CFO)* chat model moved to node v1.3 with the Responses API enabled. GPT-6 Luna refuses function tools on `/v1/chat/completions` ("Function tools with reasoning_effort are not supported").
- Prompts unchanged (`cfo-v1.0`).

## [1.2.0] - 2026-11-27
- **Expense Intake**: new *Restore verdict* Set node after *Log jailbreak attempt*. The Postgres insert replaced the item, and `$('Is jailbreak?').first()` returned null. As a result, jailbreak comments reached extraction empty and were answered with `RECEIPT_UNREADABLE`.
- **Expense Intake**: *Guard verdict*: when only the regex flags a comment (and the model does not), the matched phrases are replaced with `[премахнато]` instead of dropping the whole comment.
- **Expense Intake**: `receipt_date` is validated in *Policy input* (`YYYY-MM-DD` and `DateTime.fromISO().isValid`). *Save expense* uses `NULLIF($4,'')::date`. Postgres folded the old `CASE … THEN $4::date` at plan time and failed on empty dates.
- **All error branches**: log `$json.message` (where n8n puts the error text on error outputs) instead of `[object Object]`.

## [1.1.0] - 2026-11-26
- **TEST ONLY: Policy harness**: Execute Workflow runs in `each` mode. In `once` mode only the last branch's item came back, because the policy branches merge into one NoOp across several runs.

## [1.0.0] - 2026-11-26
Initial version.
- **Expense Intake**:
  - Webhook (multipart: `firstName`, `lastName`, `employeeId`, `comment`, `imageUrl`, file `receipt`).
  - Employee lookup in `users`: unknown employees get 403 `EMPLOYEE_NOT_FOUND` and nothing is processed.
  - Jailbreak guard (LLM + regex) → `jailbreak_attempts`.
  - Vision or text-only extraction with a Structured Output Parser.
  - Unreadable → `error_logs` + 422.
  - Policy sub-workflow.
  - Insert into `expenses` (DB error → `error_logs` + 500).
  - Embedding into `expense_embeddings` → 201.
  - Prompts `guard-v1.0` and `extract-v1.0`.
- **Expense Policy (rules)**: Policies 1-8 using only Set / If / Switch nodes.
  - BGN/EUR conversion at 1.95583; other currencies → manual review.
  - A flagged comment → manual review (`SECURITY`).
- **Error Handler**: Error Trigger → `error_logs`.
- **CFO Assistant**:
  - Webhook → CFO role check → AI Agent with Postgres chat memory, a `run_sql` tool (role `cfo_readonly`) and a `search_expenses` tool (PGVector).
  - Prompt `cfo-v1.0`.
