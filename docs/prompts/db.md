# Database: natural-language prompts

The exam asks for a schema "created through AI prompts, not hand-written SQL". The SQL in [`db/migrations`](../../db/migrations) and [`db/init`](../../db/init) was generated by Claude Code (Opus 5.5) from the prompts below. No SQL was typed by hand. Supabase + MCP was replaced by self-hosted Postgres 18 + pgvector in Docker.

## Prompt 1: roles and databases (`db/init/00-init.sh`)

> One Postgres 18 container with pgvector serves both the app and n8n.
> Create three login roles from env passwords:
> - `app_rw`: owns an `expenses` database; used by the web app and by n8n for writes.
> - `cfo_readonly`: may only SELECT business tables; its sessions are read-only, with a 5-second statement timeout, because an AI agent writes its SQL.
> - `n8n`: owns a separate `n8n` database for n8n's own storage.
>
> Enable the `vector` and `pgcrypto` extensions in `expenses`. Make `app_rw` the owner of the public schema. It must run only on first boot (docker-entrypoint-initdb.d).

## Prompt 2: core schema (`db/migrations/001_init.sql`)

> Write a migration for an expense-tracking PoC.
>
> **users**: two names of the employee, plus a free-format employee ID (unique, no fixed format), plus a role (employee or CFO).
>
> **expenses**: link to the user, receipt image URL, merchant, receipt date, amount, currency, the amount converted to BGN and EUR, and a category matching the 8 company policies (food, business meal, cigarettes, city transport/taxi, out-of-town travel, IT equipment, training, other). Also: an alcohol flag, line items as JSON, an AI description, the employee comment, status (approved / rejected / manual review) with a reason, the policy that decided it, and the raw AI output.
>
> Add tables for jailbreak attempts (raw comment, extracted instructions, cleaned comment) and for errors from n8n and the web app.
>
> Add a pgvector table that matches n8n's PGVector Store node layout (`id`, `text`, `metadata`, `embedding vector(1536)`) with an HNSW cosine index, for the CFO assistant.
>
> Use enums for status, category and role, CHECK constraints on names and IDs, and indexes for history-by-user and identity lookups (case-insensitive names). Grant `cfo_readonly` SELECT on users, expenses and embeddings only.

## Prompt 3: seed data (`db/migrations/002_seed.sql`)

> The client fills employees by hand for the PoC. Insert 6 fictional Bulgarian employees with deliberately different ID formats (to show there is no fixed format) and 1 CFO. Make it idempotent.

## Prompt 4: frontend

> Generate a Next.js (App Router, TypeScript, Tailwind v4) UI in Bulgarian, styled with the samkoBuilds brand (Charcoal Core background, Signal Orange accent, Montserrat + JetBrains Mono).
>
> Employees identify with first name, last name and ID. They upload a receipt (JPG/JPEG/PNG/WEBP/GIF, camera on mobile) with a comment, or submit text only.
>
> A History section loads automatically once the identity is valid, after each submission, and on Refresh. It shows total spent, a breakdown by category and status, and a table.
>
> A /cfo page lets the CFO chat with the AI assistant after entering name + CFO ID. The browser never talks to n8n or Postgres directly: route handlers validate input, check file magic bytes, store images and forward to n8n with a shared secret.
